The Agile Software Methodology

An iterative system development process that develops the system in “sprint” increments lasting from two weeks to two months. It concentrates on maximizing the team’s ability to deliver quickly and respond to emerging requirements.

Scrum Framework

A method to keep the agile system development effort focused and moving quickly.

Product Owner (PO)

Represents the project stakeholders and is responsible for communicating and aligning project priorities between the stakeholders and development team.

Scrum Master (SM)

Responsible for coordinating all activities.

Development Team

A self-organizing group of professionals who build and test the working product.

Extreme Programming (XP) Discipline

XP promote s incremental development of a system using short development cycles to improve productivity and accommodate new customer requirements.

1. Pair Programming

Two developers work at a single screen. One writes code ("Driver"), while the other reviews each keystroke and strategizes architecture ("Navigator").

2. Test-Driven Development (TDD)

Follows the Red-Green-Refactor loop: Write automated failing unit tests first, write the minimal code to pass tests, then aggressively refactor.

3. Continuous Integration

Code is merged into the mainline multiple times per day. Automated test pipelines run instantly to catch regressions within minutes.

4. Simple Design

Design for today's requirements only (YAGNI principle). Do not add speculative complexity; keep the codebase clean and maintainable.

5. On-Site Customer

A dedicated business user sits directly with the development team full-time to clarify user stories, resolve ambiguities, and test prototypes.

6. Sustainable 40h Pace

Prohibits chronic overtime. Rested developers write dramatically fewer bugs, think clearly, and sustain steady output over years.

DevOps Continuous Delivery & Operations

The practice of blending the tasks performed by the development staff (Dev) and the IT operations (Ops) groups to enable faster and more reliable software releases. It is being used as part of a continuous development strategy, in which releases are launched daily.
